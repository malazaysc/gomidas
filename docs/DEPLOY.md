# Gomidas — deploying the web app

Everything here is ready to run. The only thing missing is Cloudflare access (see
[§1](#1-what-i-need-from-you)). Tracked as **GMD-60**.

---

## 0. What is being deployed

A **pure static site**. No server, no auth, no API, no database. Verified 2026-08-14: no
SharedArrayBuffer, no AudioWorklet, no service worker — so there are no COOP/COEP header
requirements and nothing to run server-side.

```bash
npm --prefix apps/web run build     # -> apps/web/dist, ~27MB, 106 files
```

The build fails loudly if anything referenced is missing, so a green build is a deployable one
(GMD-56). `apps/web/dist/` is gitignored — it is rebuilt, never committed.

### The payload budget (decided 2026-08-15)

The **20–25MB ceiling is per visitor, not total hosted footprint.** Hosted is 26.69MB and that is
fine, because almost nothing is eager:

| | size | when |
|---|---|---|
| shell — JS (brotli), fonts, HTML, kit image | ~0.9MB over the wire | always |
| `soundfont/sonivox.sf2` — fallback bank | 1.29MB | on first note |
| `instruments-gm/` — melodic packs | 9.55MB on disk, **~1MB per program used** | per program |
| `drumkits/` — drum pack | 5.43MB | first percussion note |
| `instruments/` — CC0 SFZ presets | 7.85MB | only if picked in the inspector |

A typical guitar/bass/drums score costs **~10MB**, of which ~1MB lands before the user interacts.
The rule to preserve is therefore *"no new eager fetches"*, not a cap on what sits on the CDN —
adding more melodic programs is nearly free, while making anything load on startup is not.
GMD-58 (IndexedDB caching) makes a repeat visit shell-only.

**Why Cloudflare Pages** over Netlify/Vercel: unmetered bandwidth. At roughly 10MB per cold
visit the 100GB free tiers elsewhere are ~7,000 visits before it costs money, and one front-page
spike passes that. Per-file limit is 25MB; our largest file is the 5.6MB drum blob. Not GitHub
Pages: private repo, and it publishes with no access control.

## 2. Deploy

```bash
npm --prefix apps/web run build
npx wrangler pages deploy apps/web/dist --project-name gomidas
```

First run creates the project and prints the `*.pages.dev` URL. Every later run publishes a new
immutable deployment with its own preview URL, and promotes it to production.

Cache headers ship **inside the build** as `apps/web/dist/_headers`, generated by `build.mjs` so
they cannot describe a layout the build no longer produces. Cloudflare picks the file up
automatically — nothing to configure in the dashboard.

Compression is automatic: Cloudflare brotlis text at the edge. Do not pre-compress
`drumkits/*.bin` or `instruments-gm/*.bin` — they are already FLAC — nor `drumkit.webp`.

## 3. Verify after deploying

Not "the page loaded" — the failure modes here are all silent-but-wrong:

1. **Console says `backend ready (web)`.** If it says anything about JUCE, the wrong bundle shipped.
2. **`[Gomidas] instrument <n>: <name> — FluidR3 pack`** appears when a score loads. If it warns
   about falling back to the sonivox bank, `instruments-gm/` did not upload.
3. **`[Gomidas] drum kit: Standard (105 samples) — FluidR3 pack`** after a score with drums.
4. **Audio is not silent** — the deterministic check, since an automation tab is always
   `document.hidden` and the meters are dead:
   ```js
   // stub GomidasFiles.saveData to capture, then:
   await GomidasAudio.startRecording()   // offline bounce; analyse the WAV
   ```
5. **Cache headers landed**: `curl -sI <url>/index.html | grep -i cache-control` should say
   `max-age=0, must-revalidate`, and a `/dist/*.js` URL should say `immutable`.

---

## 4. Rollback

Cloudflare keeps every deployment. *Pages → gomidas → Deployments → ⋯ → Rollback* is instant and
needs no rebuild. There is no state and no database, so a rollback is total.

## 5. If we use a VPS instead

Same files, so this is not a lock-in decision — `apps/web/dist` is the whole artifact.

Use **Caddy**, not nginx: automatic HTTPS in about five lines versus nginx + certbot.

```caddy
gomidas.example.com {
    root * /srv/gomidas
    encode zstd gzip
    file_server
    header /dist/*      Cache-Control "public, max-age=31536000, immutable"
    header /index.html  Cache-Control "public, max-age=0, must-revalidate"
}
```

Note that `_headers` is a **Cloudflare Pages** file — a VPS ignores it, so the rules above have to
be restated in the server config. Put Cloudflare in front as a CDN either way, or a single region
serves the 5.4MB drum pack across the Atlantic on every cold visit.
